# XeroxYT-NTv7 for GAS：GitHubから自動更新

GASには固定の読み込み用 `Code.gs` だけを置きます。実際のサーバー処理（`gas/server/Runtime.gs`）、HTML（`gas/Index.html`）、ビルド済みJS・CSSをGitHub Actionsでまとめて公開し、GASから読み込んで実行します。

## 初回・従来版からの切り替え

1. GASの既存 `Code.gs` の全文を、このフォルダの最新 `Code.gs` に置き換えて保存。
2. `appsscript.json` の `runtimeVersion` を `V8` に設定。このフォルダのマニフェストをそのまま使用できます。
3. 下表のスクリプトプロパティを登録。すでに設定済みなら変更不要。`xyg:` から始まるセッション保存用プロパティは削除しないでください。
4. GitHub Actionsの **Publish GAS assets** が成功し、`gas-runtime/gas/web/release.json` に `server` と `serverHash` が含まれていることを確認。
5. 「デプロイを管理 → 既存デプロイの鉛筆 → 新しいバージョン → デプロイ」。同じ `/exec` URLを維持。
6. 公開リンクを再読み込み。認証がすでに失効している場合だけ一度ログインし直します。

**これ以後、通常のサーバー処理・HTML・画面修正ではGASへの貼り替え・再デプロイは不要です。** GAS側のIndexファイルは使わなくなるため、残していても削除しても構いません。

新規プロジェクトでは `Code.gs` と `appsscript.json` だけをコピーし、ウェブアプリとして公開します。実行ユーザーは自分、公開範囲は利用対象に合わせます。

| スクリプトプロパティ | 設定内容 |
|---|---|
| `API_BASE_URL` | 自分のAPIのHTTPSオリジン。末尾の `/api` は付けない |
| `API_SHARED_SECRET` | API側に設定した共有鍵。GAS専用鍵を追加したAPIではその専用鍵 |
| `ACCOUNT_BASE_URL` | 別のアカウントAPIを使用する場合のみ設定。同じAPIなら省略 |
| `UPSTREAM_ORIGIN` | `https://script.google.com`。自前APIでは許可Originも合わせる |
| `ASSET_REPO` | `Xerox-Pro/XeroxYT-NTv7-for-GAS`。Forkした場合は自分のリポジトリ |
| `ASSET_BRANCH` | `gas-runtime`。通常は省略可 |
| `RUNTIME_REF` | 通常は未設定。ロールバック時は過去の公開済みリリースのコミットSHA |

自前APIの構築は [API_SETUP.md](API_SETUP.md)、既存API用のGAS専用鍵の入口は [cloudflare/README.md](cloudflare/README.md) を参照してください。パスワードや共有鍵をGitHubへ書かないでください。

## 更新の流れ

1. `gas/server/Runtime.gs`、`gas/Index.html`、`src/` などを編集してmainへ反映。
2. Actionsがテスト・型チェック・ビルド・生成JSの起動確認を実行。
3. `gas-runtime`へJS/CSS・アイコン・サーバー処理とHTMLを含む `server-runtime.json` を保存し、同じコミットを指す `release.json` を公開。
4. 固定GASローダーが最新版を取得。公開済みの同一コミットからサーバー・HTML・画面資産を読み込むため、更新途中のファイルが混ざりません。

公開後、ローダーのリリース確認キャッシュは最大60秒です。開いている画面は再読み込みしてください。処理本体はGAS上で実行し、API通信は引き続き `google.script.run → GAS → API` を通ります。ブラウザへAPI接続先や共有鍵を渡しません。

**GASの実ファイルを自動で書き換える仕組みではありません。** 固定ローダーがGitHubから読み込んだサーバーコードを実行します。権限追加・マニフェスト変更・新しい公開エントリーポイント追加・ローダー自体の修正には、GAS側の更新や再認可が必要な場合があります。既存の外部通信権限だけで動く処理を対象とします。

## 読み込み失敗・ロールバック

- 取得ファイルのSHA-256をリリース情報と照合し、破損やバージョン不一致のファイルは実行しません。
- GitHubの取得失敗・新しいコードの構文エラー時は、取得と構文確認に成功した前の版がGASキャッシュに残っていれば使用します。
- キャッシュの保存期間は最大6時間で、Googleの判断で早期削除もあります。初回アクセス時やキャッシュ消失時にGitHubが停止している場合は利用できません。
- 実行開始後に発生したエラーでは旧版への再実行をしません。登録・送信などの二重実行を防ぎます。
- 以前の正常な **リリース情報が存在する** gas-runtimeコミットSHAを `RUNTIME_REF` に設定すると固定できます。旧形式でserverを含まないリリースは新ローダーの対象外です。通常更新へ戻すときはこのプロパティを削除します。

リポジトリのコードを変更できる人は、GASの認可された権限で動くサーバー処理も変更できます。自分が信頼するリポジトリだけを設定してください。SHA照合は破損・混在の確認であり、リポジトリ自体の乗っ取りへの署名検証ではありません。

## ログイン保持・端末データ

サイトのセッションCookieは、端末ごとのランダムなトークンに対応させてGASのスクリプトプロパティへ保存します。キャッシュが消えても期限内なら復元します。ログアウトで保存済みセッションを削除し、APIによる失効や期限切れは迂回しません。

端末識別トークンはlocalStorageとSecure・Partitioned Cookieを併用します。ブラウザがCookieを制限する場合はlocalStorageを使用します。共有鍵・サイトの実Cookie・パスワードはブラウザへ返しません。GAS専用API入口を適用したAPIでは、利用中の有効なセッションを1年先へ自動延長します。

通信・認証確認の失敗時もローカル履歴を残し、復帰時に再接続します。認証を確認できない間はAPI側の保護された操作を利用できません。マイページの「ローカルデータ（この端末）」から保存件数確認・JSON書き出しができます。動画本体は保存しません。

GASのiframe制約、ブラウザの保存領域削除、API側のセッション失効まで含めて永久にログインを保証することはできません。スクリプトプロパティにも保存容量・読み書き割当があるため、大人数向けには専用DBが必要です。

## 対応範囲と検証

元サイトのReact/CSS、スマホ・タブレット・PCの表示、GAS向けviewport補正を維持します。Shortsの表示中の動画だけ詳細取得し、重複GETを共有、公開データのみ短時間キャッシュ、フィード優先で同時RPCを最大6本に制限します。

JSON通信が対象です。動画バイナリ・Range中継、GAS版PWA・オフライン実行、一部SNS OAuthの戻り先には制約があります。外部の埋め込みプレイヤーやCDNのURLはブラウザに表示されます。全機能の完全互換や常時バックグラウンド稼働を保証しません。

```sh
npm ci --ignore-scripts
npm test
npm run lint
npm run build
npm run test:gas:bundle
```

テストはGASサービスの模擬環境でローダー・セッション保持・API中継・更新/失敗時の動作を確認し、生成JSもDOM模擬環境で確認します。利用者のGASアカウントへの公開、GAS実環境での動作と実機動画再生は別途確認が必要です。
